### Post-hoc parser note (not preregistered; labelled as such)

gpt-oss-120b's strict-v1 `parse_failure`s are 32 rows, all in application:
27 natural_language and 5 executable_rule. On inspection, **26 of the 32 are
refusals** ("I’m sorry, but I can’t comply with that request."). strict-v1
misses them because they use a typographic apostrophe (’), while its refusal
patterns match only the ASCII one. The other 6 are real format errors (e.g.
an actor name where a filename was asked for).

None of this changes accuracy, the worst-case gap, or disagreement, since a
refusal and a parse failure are both "not correct". It does change the
direction: **gpt-oss-120b's natural-language errors are fail-closed
(allow→deny), not fail-open.** That's the opposite of Qwen3-8B in Phase 0,
where all 50 flips were deny→allow. The strict-v1 flip counts above show
0 / 0 for gpt-oss only because of this parser gap.

Fixing it means a new parser version (strict-v2: Unicode apostrophes),
logged in `docs/CHANGELOG.md` and applied to every run. I've proposed it as a
change before Phase 2, not applied it here.

## Result: neutral

- **Current dense models (Qwen3.8-27B, Gemma-4-31B) are invariant** on these
  toy worlds. This matches the Phase-0 ≥27B models.
- **gpt-oss-120b is the exception.** Its application accuracy on the
  natural-language rendering is 92.5% vs 100% for decision_owner, json, and
  permission_table, and 8.9% of world-assignments disagree across renderings.
  The errors are almost all **refusals**: the model declines to choose rather
  than choosing the unauthorized value.
- **Interpretation is 100% for all three models and every rendering.** For
  gpt-oss, the natural-language effect is therefore an interpretation-correct
  / application-refused dissociation that depends on the rendering.

## Conclusion & implication

On single-scope toy worlds, rendering sensitivity in current open models is
not a capability gap of dense instruction models. It does appear in a
reasoning-native, safety-tuned model (gpt-oss), and there it shows up as
over-refusal on one rendering (natural language) rather than as unauthorized
actions.

Across Phase 0 and this addendum, the effect's **direction depends on the
model**: fail-open for a small model (Qwen3-8B), fail-closed for gpt-oss. That
fits the plan's emphasis on reporting error direction. It argues for keeping
both deny→allow and allow→deny as primary flip metrics in Phase 2, and for
fixing the parser's apostrophe handling (strict-v2) before then.

For G0, Jerzy decides. The addendum shows that "invariant at scale" holds
for dense models on easy worlds, but not uniformly across current model
families. Behavioral evidence only.
