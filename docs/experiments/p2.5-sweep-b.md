# Phase 2 sweep B: 27–31B models and controls on T1 and T2 (P2.5)
- status: done
- result: **positive (descriptive)**. All four configurations have a non-zero
  T2 worst-case gap (0.7–45.7 pp; every 95% CI excludes 0). Qwen3.8-27B's
  45.7 pp gap is almost entirely a format failure on Rego (47.9% parse
  failures, every one at the 256-token limit). Its T1 gap on the same rows is
  4.8 pp. Thinking on reduces the gap to 0.7 pp. Under the preregistered
  rule the FP8 control stays in the primary table. Holm inference and the
  scaling test wait for P2.9.

## Question / hypothesis

This report answers Q1–Q3 of `docs/prereg/phase2.md`, without any directional
prediction, for the 27–31B sweep configurations, and it applies the
quantization control:
- **Q1.** Does application accuracy depend on the rendering? (worst-case gap)
- **Q2.** What is the error direction?
- **Q3.** Is the interpretation/application dissociation rendering-dependent?
- **Quantization control.** Does Qwen3.8-27B-FP8 differ from bf16 by as much
  as the rendering effect?

Q4 (scaling) needs the whole sweep.

## Method

- **Data.** The frozen Phase-1 benchmark v2: 1,984 worlds (544 real, 1,440
  synthetic), six renderings, 172,296 rows (95,232 application). Dataset
  sha256 `0b602a1701bc52aaaf676973f24ea87b1e27acd9029f5e0523174d51894a4f83`.
- **Config.** `configs/authinv/t2.yaml`, seed 20261010, temperature 0.
  - `max_tokens` 256. For Qwen3.8-27B thinking: 4,096 tokens and
    `max_model_len` 12,288.
  - **Parser `json-strict-v3`** (prereg amendment 2026-10-14; see
    *Parser fix* below). Every T2 run in this report was generated under
    `json-strict-v2` and re-scored offline under v3.
- **Code and hardware.**
  - Inference used git `a429129` (`main`). Between it and the parser-fix
    commit, only `docs/PLAN.md` changed.
  - Software: vLLM 0.29.0, torch 2.13.0+cu130, transformers 5.16.1.
  - Hardware: one NVIDIA H100 PCIe (GPU 7).
  - Re-scoring used git `318bc5c` from a clean checkout (`dirty: false`).
- **GPU settings.**
  - GPU 7 was free for these runs, so every run used
    `--gpu-memory-utilization 0.9` (approved by Jerzy).
  - Qwen3.8 runs also used `--max-num-seqs 128`. Qwen3.8 is a hybrid
    Mamba-attention model, and vLLM's default of 1,024 concurrent sequences
    exceeds its Mamba cache ("max_num_seqs (1024) exceeds available Mamba
    cache blocks (129)").
  - Both settings change throughput only: decoding is greedy.
- **Tiers.**
  - **T2** (headline): greedy generation of all 172,296 rows.
  - **T1**: candidate log-probability margins on the 95,232 application rows,
    using the vLLM backend.
  - T1 is not defined for thinking-on models (prereg).
- **Statistics.** The world is the unit of analysis. CIs are world-clustered
  percentile bootstraps with 4,000 replicates. Accuracies are world means, so
  they can differ slightly from a pooled row count. A p of 0 means
  p < 1/4,000 before the factor of two.

Reproduce, on an H100 inside `vllm/vllm-openai:v0.29.0` with `cedarpy==4.12.1`
installed:

```sh
  case $m in qwen3_8*) S="--max-num-seqs 128";; *) S="";; esac

    --config configs/authinv/t2.yaml --dataset $D --model $m $G $S

# T2 runs generated before 2026-10-14 were scored with json-strict-v2; re-score each with v3:
python3 scripts/authinv_eval.py rescore --config configs/authinv/t2.yaml --run outputs/<T2 run>
```

### Parser fix (`json-strict-v3`, prereg amendment 2026-10-14)

The Procedure section of the prereg says a thinking model's leading `<think>`
block is stripped before parsing. `json-strict-v2` did that only for a block
that opens with `<think>`.

Qwen3.8's chat template puts the opening `<think>` into the prompt when
thinking is on. The output therefore starts with the reasoning and closes it
with `</think>`:

```
…r1 applies? It allows merge any Repo, not delete. So no allow. Deny. …
</think>

{"decision": "deny"}
```

Under v2 the thinking run scored **0.0%** on every rendering: 96.9–99.1%
parse failures and 0.9–3.1% abstains on application. The abstains came from
words such as "unclear" inside the reasoning.

v3 also strips everything up to the first `</think>` when the output contains
no `<think>`. `authinv_eval.py rescore` re-parses saved outputs only. It
refuses unless the old config differs only in `parser_version` and v2
reproduces every recorded category; both held for all 10 Phase-2 T2 runs.

## Decision rule (pre-registered, `docs/prereg/phase2.md`, commit `91cf920`)

- The primary metric is the T2 application worst-case gap, reported with its
  CI and taken from the point estimates.
- No per-model pass/fail threshold was preregistered. Significance is judged
  on the Holm-adjusted rendering contrasts across all 12 sweep models (72
  tests, α = 0.05) in P2.9.
- **Quantization control.** If the largest absolute per-rendering
  FP8 − bf16 accuracy difference is at least the bf16 worst-case gap, the
  quantized configurations move to a secondary table.
- Effect sizes come first.

## Result

**Positive (descriptive), pending the P2.9 family-wise inference.**

**Q1.**
- Every configuration's T2 worst-case gap is above zero, with CIs clear of
  zero: Qwen3.8-27B 45.7, FP8 15.4, thinking on 0.7, Gemma-4-31B 2.4 pp.
  Re-selecting best and worst inside each bootstrap replicate changes no gap
  by more than 0.1 pp.
- **Qwen3.8 thinking off.** The gap is driven by Rego, and it is a gap in
  following the answer format.
  - Rego T2 parse failures are 47.9% (bf16) and 13.4% (FP8), and they hit the
    token limit.
  - When the model does answer, Rego accuracy (95.0 / 91.9%) is in the range
    of the other renderings.
  - T1 scores the two answers directly, so format can't fail there. It finds a
    gap of 4.8 pp for both precisions, still with Rego worst.
  - On real worlds the T2 gap is 6.0 / 2.6 pp. On synthetic worlds, where Rego
    accuracy is 33.8 / 73.9%, it is 60.8 / 20.5 pp.
  - So on T2, part of the rendering effect is **whether the model answers at
    all**, and executable Rego triggers unrequested step-by-step reasoning
    far more than the other renderings.
- **Thinking on and Gemma-4-31B.** Both have small gaps.
  - Thinking on: 0.7 pp, with 98.9% of instances correct under all six
    renderings.
  - Gemma-4-31B: 2.4 pp on T2 and 2.2 pp on T1.
  - For both, NL is the worst rendering.

**Q2.**
- **Thinking-off Qwen3.8 fails closed more often than open:** allow→deny is
  3–12% and deny→allow 2–8%.
- **Gemma-4-31B and thinking-on Qwen3.8 fail open more often than closed:**
  - Gemma-4-31B: NL deny→allow 4.8% vs allow→deny 1.7%.
  - Thinking on: NL 1.3% vs 0.5%.
- **NL has the highest deny→allow rate in all four configurations,** on T2 and
  on T1. That matches sweep A, where NL was highest in five of six models.
- **Instance-level fail-open flips** affect 1.4% (thinking) to 13.2% (FP8) of
  instances.

**Q3.**
- Applying a policy wrongly despite interpreting it correctly is rare here
  (0.2–8.2%).
- For the thinking-off Qwen3.8 configurations, the rate varies across
  renderings: 0.8–3.4% (bf16) and 2.0–8.2% (FP8).
- Interpretation accuracy is high for thinking on (97.8–99.5%) and Gemma-4-31B
  (75.6–92.0%). For thinking-off Qwen3.8 it is 56–70% outside Rego and
  6.0 / 21.0% on Rego. Rego's interpretation parse failures are 92.7 / 74.0%.

**Quantization control.** Under the preregistered rule, FP8 stays in the
primary table (30.1 < 45.7 pp). The bf16/FP8 difference sits entirely in
format compliance on Rego. On decisions, T1 shows ≤ 1.0 pp per rendering.

**T1 vs T2.**
- Where T2 parses, T1 tracks it: Gemma-4-31B has 99.7% row agreement, and the
  gaps are 2.2 vs 2.4 pp.
- For thinking-off Qwen3.8, T1 gives the decision-level gap (4.8 pp) without
  the format failure.
- All three T1 models have matched candidate token counts (6 / 6).

## Conclusion & implication

- **The rendering effect persists at 27–31B without reasoning.** Gemma-4-31B
  still has a 2.2–2.4 pp gap, mostly fail-open on NL. Thinking-off Qwen3.8
  has a 4.8 pp decision gap on T1.
- **Reasoning removes most of it.** Qwen3.8-27B with thinking on reaches
  ≥ 99.1% on every rendering (gap 0.7 pp). The cost is a 4,096-token budget
  versus 256. This is the strongest data point so far for P2.9's
  reasoning-on/off contrast, and Phase 3's mitigation comparison should
  include it as a baseline.
- **Executable renderings can break the answer format.** With thinking off,
  the same model writes reasoning it was not asked for on Rego. Under a fixed
  token budget, that turns into non-answers: half the rows for bf16. For a
  deployed agent, a non-answer is a failure mode in its own right. T3
  (P2.8) should record it.
- **Quantization doesn't change decisions** (T1 ≤ 1 pp). It changes how often
  the model complies with the format on Rego. A comparison between FP8 and
  bf16 needs to say which of the two it measures.
- **Not claimed.** These are behavioral results (accuracy and likelihood
  margins). They say nothing about the models' internal mechanisms. No
  Holm-adjusted significance or scaling claim is made until the sweep is
