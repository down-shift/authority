## Question / hypothesis

This report closes Phase 2 (`docs/RESEARCH_PLAN.md` §3). It assembles the
headline tables across the three tiers. It also runs the two sweep-level
analyses the preregistration left for P2.9: the T2 Holm family and the
scaling test.

The questions come from `docs/prereg/phase2.md` (T1/T2) and
`docs/prereg/phase2-t3.md` (T3). Neither file states a directional
prediction.
- **Q1.** Does T2 application accuracy depend on the rendering? Measured by
  the worst-case gap.
- **Q2.** What is the error direction (deny→allow vs allow→deny), and does
  it depend on the rendering or the model?
- **Q3.** Is "interpretation correct but application wrong" (the
  dissociation) rendering-dependent?
- **Q4.** How does the T2 worst-case gap relate to parameter count?
- **Q5–Q7** (T3): the UIR gap on deny requests, T2→T3 transfer, and
  refusal, completion and protocol failure. Answered in P2.8 and
  summarised here.

**Gate 2** (RESEARCH_PLAN §3): all sweep runs are complete with frozen
datasets, provenance and bootstrap CIs, and the figures are auto-generated by

## Method

**Inputs.** No model was run in this step. `configs/authinv/phase2_figures.yaml`
names the analysed runs: 12 T2 runs, 9 T1 runs and 12 T3 runs. These are the
runs the P2.4, P2.5, P2.6 and P2.8 reports analysed, as follows:
- **T2.** The `json-strict-v3` runs: ten re-scored offline in P2.5 and the two
  sweep-C runs generated under v3.
- **T3.** `agent-v3` for the 10 non-harmony models and `agent-v4` for both
  gpt-oss models.
- **T1** is not defined for gpt-oss or for the thinking-on configuration
  (prereg).

`tab_runs.tex` and `phase2_tables.md` list every run directory.

**What the script does.** `scripts/authinv_figures.py`:
1. **Checks each run before using it** and refuses the whole set if any check
   fails:
   - `run_status` is complete with the expected row count (172,296 T2;
     95,232 T1 and T3);
   - the frozen dataset sha256 is `0b602a17…`;
   - the model revision equals the pin in `configs/authinv/models.yaml`;
   - each T2 run carries the hash of the current `configs/authinv/t2.yaml`;
   - with `--verify-artifacts`, every file in each run's SHA-256 manifest is
     re-hashed.
2. **Reads each run's `metrics.json`**, as written by the runner that
   produced it. World-clustered percentile bootstrap, 4,000 replicates.
3. **Computes the cross-model analyses the preregistrations define:**
   - **T2 Holm family:** 12 × 6 = 72 rendering contrasts (rendering minus the
     mean of the other five), α = 0.05.
   - **T3 Holm family:** the separate 72-contrast family. It reproduces
     P2.8's adjusted p-values exactly.
   - **Scaling:** Spearman ρ of `params_b` (registry) vs worst-case gap, with
     a two-sided permutation p from 20,000 permutations. Seeds are 20261010
     for T1/T2 and 20261013 for T3, each tier's preregistered analysis seed.
     The T2 test over all 12 configurations is the preregistered Q4. The
     versions without FP8 and thinking (10 configurations), on T1 and on T3
     are descriptive.
   - **Quantization control:** FP8 − bf16 for Qwen3.8-27B, per rendering.
4. **Writes outputs** to `paper/figures/`: 7 PDF figures, 11 LaTeX tables, the
   same tables in Markdown (`phase2_tables.md`), and `phase2_summary.json`
   with the distilled numbers and the per-run check. A second run produced
   byte-identical files.

**Cross-check.** The preregistered aggregator,
`scripts/authinv_eval.py aggregate`, gives the same T2 numbers over the same
12 runs: the same 72 Holm-adjusted p-values (59 below 0.05), all 12 gap
p-values below 0.05 after Holm, and ρ = −0.211. Its p is 0.503 rather than
0.511 because it uses permutation seed 0.

**Analysis-code correction (disclosed).** Spearman ρ uses average ranks for
ties (the standard definition). `invariance.spearman_with_permutation` used
a double `argsort` instead, which broke ties by input order. Three sweep
configurations share 27.8B parameters (Qwen3.8-27B bf16, FP8 and thinking),
so the old code made ρ depend on the order of the model keys.
- As coded, the T2 aggregate (keys sorted by name) gives ρ = −0.287
  (p = 0.36).
- With average ranks it gives ρ = −0.211 (p = 0.51).
- Both are far from significance, so the Q4 conclusion doesn't change.
- The function now uses `scipy.stats.rankdata`, and a test covers ties. Logged
  in `docs/CHANGELOG.md`.
- The P2.8 report's descriptive T3 scaling values move from −0.80 to −0.79
  and from −0.76 to −0.75. They are corrected there as an erratum.

## Decision rule (pre-registered)

- **Primary metric.** The T2 application worst-case gap, reported with its CI
  (`docs/prereg/phase2.md`, commit `91cf920`, 2026-10-08 17:34 UTC, before
  the first sweep run at 17:46 UTC). For T3, the worst-case UIR gap on deny
  requests (`docs/prereg/phase2-t3.md`, commit `4694983`). No per-model
  pass/fail threshold was preregistered.
- **Significance.** Holm over the 72 (model, rendering) T2 contrasts at
  α = 0.05; a separate 72-contrast T3 family. Effect sizes lead.
- **Q4.** Spearman ρ between parameter count and T2 worst-case gap over the
  12 sweep configurations, with a two-sided permutation p from 20,000
  permutations. It is reported once more without the FP8 and thinking
  variants, descriptively.
- **Quantization.** If the largest |FP8 − bf16| accuracy difference reaches
  the bf16 worst-case gap, the quantized configurations leave the headline
  tables.
- **Gate 2** is the RESEARCH_PLAN §3 criterion above. This report recommends;
  Jerzy decides.

## Result

**Positive for Q1–Q3 (and Q5–Q7 from P2.8); null for Q4.**

**Q1. The rendering effect is present in every configuration.**
- **Every gap is above zero.** All 12 T2 gaps exceed zero with CIs clear of
  it, and 59 of 72 contrasts survive Holm.
- **Gap sizes by group:**
  - The six non-reasoning configurations below the ceiling (Qwen3.5-4B/9B,
    Gemma-4-E4B/12B, Ministral-3-14B, Llama-3.3-70B W8A8) have T2 gaps of
    4.3–7.3 pp. Only 51–75% of their instances are correct under all six
    renderings.
  - The four near-ceiling configurations (gpt-oss-20b, gpt-oss-120b,
    Qwen3.8-27B thinking, Gemma-4-31B) are at 0.7–2.4 pp.
- **T1 agrees with T2.** T1 gives gaps of 4.4–5.8 pp for the same six models
  and 2.2 pp for Gemma-4-31B (T2: 2.4). T1 and T2 name the same worst
  rendering in 8 of
  the 9 models with both tiers. The exception is Gemma-4-E4B, where T2's NL
  and table differ by 0.1 pp. The effect is therefore in the models' decision
  likelihoods, not only in their sampled text.
- **No single rendering is worst.**
  - Worst: Rego in 5 configurations (Qwen3.5-4B/9B, Ministral, Qwen3.8-27B
    bf16 and FP8), NL in 5 (Gemma-4-12B, Gemma-4-31B, gpt-oss-20b/120b,
    Qwen3.8 thinking), table and JSON in one each.
  - Best: owner in 5, Cedar in 3, Rego in 3, JSON in 1.
  - Rego is worst for Qwen3.5-4B/9B, Ministral and Qwen3.8-27B (bf16 and
    FP8), and best for Gemma-4-12B, gpt-oss-20b and Qwen3.8 thinking.
- **NL** is significantly below the mean for the strongest models: all four
  near-ceiling configurations, Gemma-4-E4B and Gemma-4-12B. It is
  significantly above the mean for Qwen3.5-4B/9B and Ministral, and for
  Qwen3.8-27B bf16, where the mean of the others includes its failed Rego
  rows.

**Q2. The direction depends on the model; NL leaks toward allow.**
- **Highest deny→allow.** NL has the highest T2 deny→allow rate in 11 of 12
  configurations. The exception is Gemma-4-E4B: table 25.9% vs NL 25.7%.
- **Models below the ceiling fail closed more often than open.** For the
  eight non-reasoning configurations, the mean allow→deny rate across
  renderings is 7.7–51.6%, against a deny→allow rate of 3.7–19.9%.
- **The near-ceiling configurations make few errors.** Those on deny rows
  concentrate on NL: NL deny→allow is 1.3–4.8%, and every other rendering is
  at most 1.9%.
- **The direction is partly a property of the rendering, not only of the
  model.** Rego has the lowest deny→allow and the highest allow→deny rate for
  the Qwen3.5 models and Ministral.

**Q3. The dissociation exists and varies with the rendering. This is
descriptive; there is no preregistered test.**
- **Where it is common.** P(application wrong | interpretation correct) by
  rendering:
  - 13.1–16.6% for Qwen3.5-4B;
  - up to 10.2% for the other non-reasoning models below the ceiling
    (Gemma-4-E4B 7.6–10.2, Qwen3.5-9B 5.9–8.9, Llama 8.0–9.0, Ministral
    2.9–10.0, Gemma-4-12B 3.3–5.6);
  - at most 1.0% for the four near-ceiling configurations.
- **Spread within a model.** It reaches 7.1 pp for Ministral (Cedar 2.9% vs
  JSON 10.0%), 6.2 pp for FP8 (Rego 8.2%) and 3.5 pp for Qwen3.5-4B. For Llama
  it stays within 8.0–9.0%.
- **Interpretation gaps exceed application gaps** in 8 of 12 configurations.
  The clearest cases are Gemma-4-12B/31B, Ministral and Llama, at
  9.5–16.4 pp. For the two Qwen3.8 thinking-off configurations the
  interpretation gap (62.5 and 49.2 pp) is again Rego format failure.

**Q4. No scaling trend on T2.**
- **Preregistered test:** ρ = −0.21 (permutation p = 0.51, n = 12), and
  −0.26 (p = 0.47) without the 27B variants.
- **Small gaps go with reasoning output, not with size.** The small T2 gaps
  belong to the reasoning-output configurations (gpt-oss-20b, gpt-oss-120b,
  Qwen3.8 thinking) and Gemma-4-31B. Llama-3.3-70B W8A8 (5.7 pp) sits with
  the 4–14B models.
- **T3 does show a strong descriptive trend** (ρ = −0.79, p = 0.003). The
  same reasoning-vs-non-reasoning split runs through it, and these 12
  configurations cannot separate size from model family and reasoning mode.
  This is a pattern across configurations, not a causal size effect.

**Quantization.** The preregistered rule is not triggered: FP8 − bf16 is at
most 30.1 pp (Rego) on T2 against a 45.7 pp bf16 gap. The FP8 and W8A8
configurations stay in the headline tables, as decided in P2.5. On decisions,
the FP8 differences are small: at most 1.0 pp on T1 and 2.2 pp on T3.

**T2 → T3 (Q5–Q7, from P2.8).** The tiers agree in aggregate but not row by
row:
- T2 deny→allow tracks T3 UIR across the 72 (model, rendering) cells
  (ρ = 0.76).
- T2 and T3 name the same worst rendering in only 6 of 12 configurations.
- 29–84% of T3 violations fall on rows that T2 answered correctly with deny.

## Gate 2 recommendation

**Recommend: pass.** Every Gate-2 criterion is met (table above). The
decision is Jerzy's (`docs/RESEARCH_PLAN.md` §3; G2 is a `[HUMAN]` step).

Points to weigh, none of which blocks the gate in my reading:
1. **Q4 is null on T2.** The paper cannot claim that scale reduces the
   rendering gap. The data support "reasoning-output configurations have
   small gaps; dense non-reasoning models up to 70B do not".
2. **Qwen3.8-27B (thinking off) is a format case on T2.** Its headline T2 gap
   (45.7 pp) is mostly Rego non-answers at the 256-token limit. Tables should
   show its T1 gap (4.8 pp) beside it. For Phase 3, "closing the worst-case
   gap" for this model would mostly measure answer format.
3. **T3 open items before T3 is reused in Phase 3** (P2.8):
   - The `respond` tool shadows a policy action named `respond` in 10
     CedarBench worlds (≤ 0.1 pp effect). The fix needs a sandbox version
     bump.
   - Whether an object-valued `resource` stays a protocol failure is a
     preregistration choice for Phase 3.
4. **Not run:**
   - the optional models (`phase2_optional`; outside Holm and scaling);
   - a bf16 Llama-3.3-70B. The W8A8 anchor has no bf16 comparison, so nothing
     is claimed about W8A8 itself.
5. **Implication for Phase 3** (a suggestion, not a plan change):
   - **Different worst renderings.** On T2, Rego is worst for Qwen3.5,
     Ministral and Qwen3.8 thinking-off, and NL for Gemma-4-12B/31B and
     gpt-oss. A canonicalization arm therefore has to close gaps that start
     from different renderings.
   - **Near-ceiling models.** gpt-oss-20b/120b, Qwen3.8 thinking and
     Gemma-4-31B have T2 gaps of 0.7–2.4 pp and T3 gaps of at most 1.0 pp.
     They leave little room to measure closure. Gate 3 is judged on "the
     majority of models", so the Phase-3 prereg should say which models count.

## Conclusion & implication

- **The phenomenon holds across the sweep and all three tiers.**
  - Engine-certified equivalent renderings change decisions in every
    configuration (T2, Holm-corrected), in the models' log-probabilities
    (T1), and in what agents do (T3).
  - On T2 the effect is 4–7 pp for non-reasoning models below the ceiling,
    up to 70B, and 0.7–2.4 pp for the four near-ceiling configurations.
  - The risky rendering is model-dependent. NL is the most consistent
    fail-open rendering.
- **Scale alone doesn't remove it.** The preregistered scaling test is null.
  Reasoning output, not parameter count, separates the small-gap
  configurations on T2.
- **Not claimed.**
  - These are behavioral results (accuracy, likelihood margins and agent
    actions). They say nothing about internal mechanisms.
  - The T3 scaling trend, the tier-agreement counts, the dissociation
    spreads, and the T1/T3 quantization deltas are descriptive.
- **Artifacts.**
  - Figures, LaTeX tables, Markdown tables and `phase2_summary.json` are in
    `paper/figures/` (committed; regenerated from `outputs/` by the script).
  - Raw runs stay git-ignored under `outputs/` and in the V100 archives named
    above.
  - The cross-check aggregate is in `outputs/p2.9/t2_aggregate.json`.
