# Phase-1 frozen benchmark (P1.10)
- status: done
- result: data audit, not a model experiment. **1,984 engine-certified worlds** (544 real, 1,440 synthetic); **172,296 rows**
- frozen dataset: `outputs/20261008T112623005337Z_authinv_benchmark/dataset.jsonl`, sha256 `255c9ba2ed4b6483f3023a0bfb4a610ad7075e0292a0c1218b9378e3343b9380`; built from commit `0e01eaa` (clean tree)

## What

Every row is one query about one sampled request in one world, under one of
six renderings: nl_statement, owner_statement, table, json_policy,
executable (Cedar), rego.

- **application** asks "is this request allowed?". The answer is JSON
  allow/deny, and the label is the engine-certified decision.
- **interpretation** asks "which principals may do this action on this
  resource in this context?". The answer is a JSON set, the derived decision
  owners.

The two share `pair_key` (action, resource, context), so the dissociation
metric can pair them.

Each world has 2 allow and 2 deny requests, boundary requests first. Each is
asked under two **name assignments**, `orig` and `swap`:
- `swap` renames ids by a fixed derangement, applied consistently to
  entities, rules, and requests. Principals are renamed when there are at
  least 2; otherwise resources are (`swap_axis`). Every swapped policy is
  re-certified: **1,984 / 1,984**.
- The order of "allow" and "deny" in the instruction alternates
  (`option_order`).

The prompt template is `prompt-v1` (`src/authinv/benchmark.py`). It is
identical across renderings: an intro, the combining rule, the entity facts,
the policy, then the request or question. Tests check that two renderings'
prompts differ only in the policy text.

```sh
uv run --extra engines python scripts/authinv_build_benchmark.py --config configs/authinv/benchmark.yaml \
  --source synthetic=outputs/20261008T110740918826Z_authinv_synthetic \
  --source cedarbench=outputs/20261008T111239605974Z_cedarbench_import_v2 \
  --source quacky=outputs/20261008T112007561950Z_quacky_import
```

## Selection

Every source gets the same bar:
- certified on all six renderings, with the proof re-checked against the
  policy hash;
- de-duplicated by semantic hash;
- non-degenerate: ≥ 4 allow and ≥ 4 deny requests, ≥ 2 boundary per label,
  and swappable.

| source | kind | loaded | non-degenerate | capped out | selected |
|---|---|---:|---:|---:|---:|
| synthetic (P1.6.2) | synthetic | 1,440 | 1,440 | — | 1,440 |
| CedarBench v2 (P1.7.2) | real | 2,644 | 2,644 | 2,150 | **494** (105 scenarios, ≤ 25 each) |
| Quacky v2 (P1.8.2) | real | 107 | 50 | — | **50** (43 swap resources, 7 principals) |
| **total** | | | | | **1,984** (real 544, synthetic 1,440) |

The CedarBench cap (25 worlds per scenario, chosen by semantic hash) keeps
the 5 stress scenarios from dominating. Uncapped they would contribute
2,262 of 2,644 worlds.

## Caveats

- **Real worlds are a minority (27%).** Every table must report real vs
  synthetic separately (`source_kind` is on every row).
- **CedarBench entities are synthesized**, and a world's non-degeneracy often
  comes from replicated entities and action probes (see
  `p1.7-cedarbench-import.md`).
- **Quacky worlds** rely on wildcard witnesses and closed-world complements;
  this is flagged in each world's meta.
- **Archived.** Raw artifacts are git-ignored. The benchmark run and its
  three source runs are archived on V100 storage at
  `/var/dockerstorage/docker-jkaminskii-202512171636/authinv/phase1/`
  (2026-10-08, after the VPN came back). The archived `dataset.jsonl` sha256
  matches `255c9ba2…`.

## Conclusion

The benchmark exceeds the plan's targets: ≥ 1,000 worlds, ≥ 5 renderings,
≥ 4 requests per world, and ≥ 20k application rows per model. It's ready for
the datasheet and the human spot-check (P1.11, G1). Model results never touch
these files. Any change to prompts or renderers needs a version bump and a
rebuild.
