## Method choice

The plan's `[DECISION]` allows IAM through Quacky's SMT check only if that check runs locally without pain. It does not: Quacky needs the ABC string model counter built from C++ source (`INSTALL.md` → vlab-cs-ucsb/ABC), and neither `abc` nor `z3` is installed here. So we use the **fallback**:

1. **Translation** (`src/authinv/sources/quacky.py`). Each IAM document is translated deterministically into a canonical `Policy` over a closed request universe.
2. **Independent oracle** (`src/authinv/sources/iam_eval.py`). This is a small reference IAM evaluator written separately from the translator, with its own glob matcher and condition semantics. It evaluates the **original JSON** using single-document AWS logic: explicit Deny overrides Allow, and the default is deny. Actions match case-insensitively and resources case-sensitively, with `*`/`?` globbing. `Principal` is checked only when the statement has one. Within a condition block, operators and keys AND together. A positive operator with several values is an OR, and `StringNotEquals`/`NumericNotEquals` with several values hold only when the request value is none of them. The evaluator refuses any document with a construct outside its subset rather than guessing.
3. **Differential test.** On every request in the universe, the evaluator's decision on the original JSON must equal the canonical reference decision, with zero evaluator errors.
4. **Certification.** `certify()` must pass on all six renderings: decode, decisions, Cedar engine plus strict typecheck, and OPA.

A file ships only if steps 3 and 4 both pass. Shipped worlds are deduplicated by semantic hash.

### Closed universe (per policy)

- **Actions**: the concrete (wildcard-free) action strings in the policy, plus one probe `authinv-probe:UnlistedAction`.
- **Resources**: the concrete resource ARNs in the policy, plus one probe `arn:aws:authinv-probe:::unlisted-resource`.
- **Principals**: for an identity policy (no `Principal` anywhere), one caller whose policy this is. For a resource policy, every named principal plus an unrelated caller `arn:aws:iam::000000000000:user/authinv-unlisted-caller`.
- **Context**: one key per condition key, using `authinv.equivalence.requests.context_values`: the policy's literals plus `__unseen__` for strings, both booleans, and c-1/c/c+1 for integers. Every request supplies every key, so absent-key behaviour is outside the universe.

**Wildcards are expanded over this universe.** A statement covers exactly the universe members its patterns match. That is exact on the universe and nowhere else. Each world records `wildcard_expanded`, and the strict count without expansion is reported below. Two more exact rewrites are applied:

- A statement whose resource or principal set is neither one member nor the whole axis is split into one rule per member.
- A positive operator with several values is split into one rule per value. Several values under a negated operator become a conjunction of `!=`.

Identifiers are mapped injectively into the renderers' `SAFE` alphabet: `:` → `.`, any other unsafe character → `_`, and condition keys → `[A-Za-z0-9_]`. For example, `s3:GetObject` → `s3.GetObject` and `arn:aws:s3:::mybucket` → `arn.aws.s3...mybucket`. The original strings are kept in each world's meta (`names`). Every world's meta also records `entities_synthesized: true`.

**Excluded and counted per construct:** `NotAction`, `NotResource`, `NotPrincipal`, every condition operator other than `StringEquals`, `StringNotEquals`, `Numeric{Equals,NotEquals,LessThan,LessThanEquals,GreaterThan,GreaterThanEquals}` and `Bool`, `…IfExists`, `ForAnyValue:`/`ForAllValues:`, policy variables (`${…}`), account or partial-wildcard principals, and non-integer numbers. Nothing is approximated.

## Caveats and implications for P1.10

- **The universe rule specified for this step starves wildcard policies.** With a universe of only "concrete strings + one probe", a statement like `Allow s3:* on arn:aws:s3:::mybucket/*` covers nothing, because no concrete object ARN exists. 197 files are excluded for this reason alone. Many others ship as tiny or one-sided worlds; for example, `s3_allow_all_except_delete/initial` ships all-deny. A **witness instantiation**, adding one concrete member per wildcard pattern (e.g. `arn:aws:s3:::mybucket/authinv-object`, or a concrete `s3:` action for `s3:*`), would recover most of these and make them non-degenerate. It changes the universe, so it is a human decision and an importer version bump, not done here.
- **Real IAM constructs dominate the exclusions.** `NotAction`, `NotResource` and `NotPrincipal` appear in 351 file-construct pairs, largely because `mutate.py` produces them. String globbing conditions (`StringLike`/`StringNotLike`), IP ranges, and policy variables cover most of the rest. Under a closed universe, NotAction/NotResource can be expanded exactly as complements, and `StringLike` over a finite value domain is exact too. Both would be plan changes.
- **The mutations are near-duplicates.** 86 shipped mutation files collapse to 19 unique worlds. P1.10 should deduplicate (done here by semantic hash) and stratify by original policy.
- **The semantics are single-document.** We evaluate one policy alone, as Quacky does. Cross-policy evaluation (identity plus resource policies, SCPs, boundaries) is out of scope. Requests always carry every condition key.
- **The SMT route was not tried beyond the install check.** If someone later builds ABC, Quacky's model counts could cross-check the closed-universe decisions, but they quantify a different, infinite request space.

## v2: wildcard witnesses and closed-world complements (P1.8.2)

Approved by Jerzy on 2026-10-08 (RESEARCH_PLAN §8, "Quacky: wildcard witnesses, exact Not* complements"). This is a data audit, not a model experiment, so there is no preregistration. The decision rule is the one from P1.8: a file ships only if the IAM evaluator on the original JSON and the canonical policy agree on every request of the closed universe (zero mismatches, zero evaluator errors) **and** `certify()` passes on all six renderings. Non-degeneracy is recorded per world and does not gate shipping; P1.10 filters on it.

### What changed (`quacky-import-v2`, `docs/CHANGELOG.md`)

- **Wildcard witnesses.** Each distinct wildcard pattern on the action or resource axis (from `Action`, `NotAction`, `Resource`, `NotResource`) adds one concrete member. Every `*` is replaced by a token and every `?` by the token's first letter. The tokens are tried in a fixed order (`ZzWitness`, `QqWitness`, `XxWitness`, `JjWitness`, `VvWitness` for actions; `zz-witness`, `qq-witness`, ... for resources), and the first one is kept that matches the fewest *other* patterns in the policy and is not already a member. Examples: `s3:Get*` → `s3:GetZzWitness`, `arn:aws:s3:::bucket/*` → `arn:aws:s3:::bucket/zz-witness`, `arn:aws:ec2:*:*:instance/*` → `arn:aws:ec2:zz-witness:zz-witness:instance/zz-witness`, `*` → `zz-witness`. `Principal: "*"` adds a witness caller `arn:aws:iam::000000000000:user/authinv-witness-caller`. The probes are kept. Each world's meta lists every witness and the other patterns it also matches (`witnesses`). In the shipped worlds, 61 of 265 action/resource witnesses also match another pattern. Every one of those patterns is strictly more general (`*`, `s3:*`, `ec2:*`, `arn:aws:s3:::*`, `arn:aws:ec2:us-east-1:123412341234:*`), so the overlap cannot be avoided.
- **Closed-world complements.** A statement with `NotAction X` covers every universe action that no pattern in `X` matches, and `NotResource` works the same way on resources. Both are written out as explicit sets. `NotPrincipal` is translated the same way only when it names `Service` principals: a service principal is a single identity, so the complement over the closed principal set is exact. `NotPrincipal` naming an AWS account, user or role stays excluded, because AWS also matches such a caller through its account ARN, which a single-identity universe does not model. Worlds that use a complement carry `closed_world_complement: true`. The complement is exact on the closed universe only, the same caveat as wildcard expansion.
- **IAM evaluator** (`iam_eval.py`). It now implements `NotAction`, `NotResource` and `NotPrincipal` (`Service` only) natively, as "matches none of the patterns" / "caller not listed". It still refuses everything else outside its subset. On documents without `Not*` it behaves exactly as v1 did.
- **Non-degeneracy** per world now uses the full P1.6 bar: at least 4 allow and 4 deny requests, each label with at least 2 boundary requests (`quacky.degeneracy`, matching `synthetic.is_non_degenerate` without its dead-rule check). In both v1 and v2 the boundary condition removes no world beyond the count condition.
- **v1 stays reproducible.** `--importer quacky-import-v1` reruns v1 and gives byte-identical `policies.jsonl` (`975e3030699c908e…`) and `equivalence.jsonl` (`73b116bcb180c12d…`), the hashes reported above.

### Result (v2)

**Positive.** Every v2 conversion is faithful to the original IAM JSON under the independent evaluator and certified on all six renderings. The changes recover the 197 wildcard-only files and all `NotAction` / `NotResource` files that have no other excluded construct. The source now gives 107 unique worlds, 50 non-degenerate (17 of them include an original), up from 28 and 5. The source is still small next to the ≥1,000-world target, so P1.10 still relies on the synthetic top-up (P1.6.2).

### Caveats (v2)

- **Witnesses and complements are exact only on the closed universe.** A world says what IAM decides for its listed actions, resources and callers. `s3:ZzWitness` stands for "some other `s3:` action", not for a real one. Renderings show the witness strings, so models see synthetic identifiers such as `s3.GetZzWitness`. P1.10's name-swap balancing should treat them like other synthesized names.
- **Universe membership drives the decision mix.** Most degenerate worlds lack allows: a broad `Deny` with a narrow `Allow` leaves few allowed (action, resource) pairs among a handful of members. Adding more witnesses per pattern would raise the counts, but it would only duplicate the same distinctions.
- **Mutations still dominate.** 84 of 107 unique worlds come only from `mutate.py` variants, which often differ from their original by one swapped element. P1.10 should stratify by original policy and report originals and mutations separately.
